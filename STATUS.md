# Статус проекта poe2-blackbox

Обновлено: 2026-09-09. Репозиторий: https://github.com/MaxTor2001/poe2-blackbox (public, ветка main).
Релизы собираются в GitHub Actions на каждый тег `v*` (Windows exe + ffmpeg, Linux бинарник).
Последний рабочий релиз: v0.1.16.

## Что это
Локальная программа для хардкора PoE2: читает Client.txt, записывает каждую смерть с контекстом.
Python 3.13, uv, click, FastAPI, SQLite, ffmpeg. Данные в папке пользователя
(%LOCALAPPDATA%\poe2-blackbox на Windows, ~/.local/share/poe2-blackbox на Linux).
Запуск: `blackbox run` (следит за логом + журнал в браузере + трей). Ещё команды: watch, serve,
import, deaths, diag.

## Готово и проверено на Windows-машине пользователя
- Разбор Client.txt: зоны, области (уровень, сид), левелапы, смерти, подключения к инстансу.
  Русский и английский клиент ("X был повержен.", "X (Класс) достигает N уровня").
- Журнал смертей: зона, уровень области, уровень персонажа, время в зоне. Сводка сверху.
- Страница персонажа /character/<name>: график уровней с метками смертей, список смертей.
- Пинг до инстанс-сервера (TCP) раз в 2с, сводка за минуту до смерти.
- Моды вейстоуна из буфера обмена (Ctrl+C перед картой).
- Клипы смертей: встроенный ffmpeg, кольцевой буфер сегментов, --clip-seconds (10..60, деф 30).
  Кодировщик авто: NVENC/QSV/AMF/x264. Запись стартует по появлению окна игры, стоп по закрытию.
  У пользователя работает через AMF (AMD iGPU); NVENC не грузится — нет nvcuda.dll (неполный драйвер NVIDIA).
- Windows-сборка без консоли, иконка в трее (открыть журнал / папку клипов / выход).
- Данные переживают обновление; лог existing Client.txt импортируется при старте (идемпотентно).

## Известные мелочи
- Клип пишет весь экран, если игра в эксклюзивном полноэкранном. Обрезка по окну работает только
  в оконном без рамки (crop DPI-aware, с фолбэком без обрезки).
- SmartScreen ругается на неподписанный exe ("Подробнее" -> "Выполнить в любом случае").
  Решение — подпись кода (SignPath Foundation, бесплатно для OSS) перед публичным релизом.

## ЗАБЛОКИРОВАНО внешним ограничением
- Снимок снаряжения PoE2: НЕДОСТУПЕН. pathofexile.com/character-window отдаёт персонажей PoE1
  (realm=poe2 игнорируется) даже с валидным POESESSID; pathofexile2.com/character-window отдаёт HTML,
  JSON-API нет; публичный ладдерный персонаж тоже 403. Единственный путь — официальный OAuth-API GGG
  с realm=poe2, регистрация приложений ЗАКРЫТА. poe.ninja получает данные именно так (партнёрский токен
  до закрытия). Функция в коде есть, отключается чисто (Unavailable/Forbidden/WrongAccount).
  Аудит защиты (резисты/HP/пороги vs моды вейстоуна) зависит от неё — тоже отложен.

## Что осталось / варианты продолжения
1. Дождаться открытия OAuth GGG (ближе к релизу 1.0 — 11 декабря 2026) -> снаряжение + аудит защиты.
2. Общая статистика по СВОЕЙ базе: анонимная отправка разборов смертей на сервер (зона, моды, уровень,
   класс, пинг) с opt-in переключателем. Нужен дешёвый VPS (Hetzner ~5€, не Amazon), правила приватности.
3. Статистика по HC-ладдеру: тоже требует OAuth (ладдер PoE2 на pathofexile2.com — SPA без открытого JSON).
4. Мелочь: остановка пингера при выходе в меню; необязательный источник снаряжения из API poe.ninja
   для проиндексированных персонажей (узко: только верхушка ладдера, мёртвых HC выбрасывают).
5. Косметика: иконки классов персонажей (не брать арт GGG без разрешения).
